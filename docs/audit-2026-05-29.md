# Полный аудит online-mafia — 2026-05-29

Многоагентный аудит: 11 finder-агентов (по подсистеме, 4 линзы — безопасность,
корректность, архитектура, тесты), каждая находка проверена двумя независимыми
adversarial-верификаторами (корректность чтения кода + реальный impact).

**Итог:** 80 сырых находок → 58 подтверждено (после верификации), 22 отклонено.
**Критичных дыр нет.** Auth/JWT, OAuth+PKCE, server-assigned LiveKit identity,
argon2id — реализованы корректно. Находки — это hardening, утечки ресурсов,
гонки в краевых случаях и техдолг (большие файлы).

Severity в таблицах ниже — после ручной перепроверки (workflow завышал часть
находок при эскалации; например path-traversal admin-gated → не high).

## ⏸ Отложено сознательно (с обоснованием)

### Гонки autoPick (#40, #41) — НЕ баг

`autoPickRoleCard` читает state без лока, но затем вызывает `pickRoleCard`,
который берёт `withLock` и ре-валидирует ход через `applyRoleCardPick`
(движок отклонит, если карта занята / picker сменился). Гонки нет — движок
под локом является шлюзом. Изменение только добавило бы риск.

### Engine-layer authz (#2, #17, #30) — defense-in-depth

`applyJudgeUnnominate/Foul/Unfoul/Remove` не валидируют `actor.isJudge`, но
service-слой (`requireJudge`) это гарантирует на всех путях. Не дыра;
консистентность движка — отдельная задача, трогающая ядро.

### Прочее (low / требует отдельной работы)

- #27 timing-enumeration при регистрации — требует реструктуризации register.
- #26 OAuth error логируется целиком — payload arctic неизвестен, риск низкий.
- #19/#28/#21 проглоченные ошибки / unhandled rejection в fire-and-forget — добавить логирование.
- #44/#49/#58 prisma: FK RESTRICT/enum-валидация на уровне БД.
- #42/#51/#54 unchecked-assertion / валидация server-data на клиенте.
- Тесты (#22/#23/#25/#52): Socket.IO auth-middleware, rate-limit, UserPage, AdminPage, MediaRoom — известный gap, новые тест-файлы.

### #31/#48/#56 (валидация формата path-параметров)

Реальный риск был только в debug-log (#5, файловый путь) — исправлен.
Остальные `:id`/`:code`/`:userId` идут в Prisma как TEXT-колонки (не native
uuid), поэтому невалидный формат → `findUnique` вернёт null → штатный
NOT_FOUND, а не ошибка БД. Дополнительная валидация косметична.
